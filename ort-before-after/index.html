Intel f16 bug in Axiya's ONNX Runtime Web build: before and after the fix

The bug: on an Intel gen-9 laptop GPU (Windows, Chrome 154, D3D12, September 2026), a GPU program that read one 16-bit number (f16) from memory got 0 for every odd-numbered element, so models gave wrong output.

What this page does: it runs one tiny model on your GPU twice, once with the last build of Axiya's ONNX Runtime Web (WebGPU) from before the fix, and once with the first build after it. It then compares each output with values computed in advance on a CPU.

What the bug depended on: the laptop's older Windows or Intel graphics driver, not the Chrome version. In October 2026 the laptop's Windows was reinstalled (build 26300) and it got a new Intel driver (31.0.101.2140). On November 27, 2026, I ran Google's own Chrome 154 test build (Chrome for Testing 154.0.8037.92) on that setup, and the old build gave correct results. So on most computers today both builds below are correct. The fixed build protects computers that still have the older setup.

Below: what the model wrote on the laptop in September (recorded), a simulation of the fault, and a live run of both builds on your GPU.

Simulation: what the fault does to what each build reads

This applies the recorded fault (when a program reads one 16-bit value at a time, every odd-numbered value comes back as 0) to a small image stored as 16-bit values. The old build reads values one at a time, so it is hit. The fixed build reads 32-bit words and splits them, so it is not. This part is a simulation, run in JavaScript, not on your GPU.

The test

ModelWhat it does
gather_f16.onnxPicks 64 rows out of a 64 x 16 table of f16 values (a Gather, as in a model's embedding lookup). All 1024 values are different and none is 0. The first wrong step on the Intel laptop was this kind of Gather.
cast_f16.onnxControl. Turns 1023 f16 values into 32-bit values and adds 0. This kernel reads 4 values at a time, not one, so it is not expected to show the bug.

The two models and the expected outputs (expected.json) come from make_model.py. Outputs are compared bit for bit. "Odd" and "even" refer to the position of the value in the f16 input.
